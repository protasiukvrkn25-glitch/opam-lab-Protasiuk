# Лабораторна робота №6 — Алгоритми підрахунку та групування

## Завдання 1. Частоти довжин слів

Текст для тестування:

> Алгоритм описує послідовність дій. Алгоритм можна записати словами, а можна записати кодом. Кодом алгоритм стає тоді, коли його виконує машина, а не людина. Одна задача — багато алгоритмів.

Підраховуються довжини слів. Пунктуація відкидається. Виводяться довжини, частота яких не менша за `K % 3 + 2`, тобто 2. Реалізовано словниковий і списковий способи.

## Завдання 2. Групування студентів

Студенти групуються за першою літерою прізвища. Для кожної групи виводяться ключ, кількість студентів і середній бал. Реалізовано `Dictionary<char, List<Student>>` та списковий спосіб без словників і множин.

## Завдання 3. Вилучення дублікатів

Використано 25 чисел у діапазоні `[1; 9]` з генератором `Random(20)`. Перший спосіб створює `HashSet` із початкового списку, тому порядок елементів не гарантується. Другий спосіб використовує `HashSet` для перевірки, чи число вже зустрічалося, а список — для збереження початкового порядку першої появи.

## Завдання 4. Спільні елементи наборів

Створено два набори по 30 чисел у діапазоні `[1; 23]` з генераторами `Random(20)` та `Random(120)`. Спільні елементи знайдено двома способами: через `HashSet` і вкладеними циклами по списках. Програма перевіряє, чи збігаються результати.

## Завдання 5. Вимірювання швидкодії

### Висновки

1. Виграш зростає зі збільшенням даних, тому що пошук у списку вимагає послідовного перегляду елементів, а пошук у `Dictionary` або `HashSet` у середньому виконується за близький до сталого час. У спискових алгоритмах може зростати кількість порівнянь.
2. На малих наборах різниця може бути непомітною: накладні витрати на створення словника або множини можуть бути порівнянними з часом простого проходу списку. Для кількох елементів список часто достатній; для частих пошуків і великих наборів словник або множина зазвичай доцільніші.
3. За швидкість словник і множина платять додатковою пам'яттю та складнішою структурою даних. Крім того, звичайний `Dictionary` не призначений для збереження порядку за ключем, а хеш-структури потребують коректного порівняння ключів і можуть мати витрати на створення та розширення.
